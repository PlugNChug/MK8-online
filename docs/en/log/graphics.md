## Local validation for the next version — menu, image and Miis

The F1 menu and the native options use the same list of upscaling methods. The launcher checks the optional components and the GPU before offering them to the game. Bilinear and FSR 1 are available in the normal installation. The choice of a new temporal provider is saved for the next time the game opens. The launcher follows the preferences saved by the game and keeps local edits in progress. A slow status query also now lets the player cancel, reopen and confirm the Nextendo dialog. The browser test holds the response of that query until after the confirmation.

The clean MK8 4.0.1 build recompiled all 484 units in an isolated folder. The full preparation took 31 min 47 s, and the immediate repeat took 46 s. The runtime update from the installer checked 13 dependencies and preserved the hashes of the game library and of the three recompiled modules.

108 Rust tests, formatting and Clippy passed. In the discovery of 431 Python tests, 430 passed on Windows. The Linux-specific input test passed in a Linux process on WSL with SDL 3.4.18. The dedicated graphics battery passed all 46 cases. With the player's private resources, the editor loaded the parts, updated face and body, saved and exported the profile. The recompiled SDK verifier accepted 62,208 appearance combinations and rejected one invalid input.

The sweep found two particle shaders from `Cnsw_57` (DLC) that failed on the mip-level query `TMML.B` at `0xb0`. Both read the static identifier of the same texture table entry. The translator now recognizes the multiplications, multiply-and-add operations and two-component sampling that preserve that register. It still refuses the case in which any destination of the operation overwrites the identifier. The two real effects reproduced the earlier failure and, after the adjustment, produced the same GLSL as the reference query with the texture explicitly bound. Both passed the shader compiler. The public tests use synthetic instructions.

In fullscreen at 1920 × 1080, the Time Trials sweep confirmed the model active at the time of capture for each of the 160 tracks (48 base, 48 DLC and 64 CTGP). All 40 processes ended normally. ## Fullscreen cursor auto-hide

The SDL window loop hides the pointer after two idle seconds while the fullscreen game window has keyboard and mouse focus. Mouse activity restores it. The in-game menu and controller setup keep it visible. The launcher and in-game Video settings share the `auto_hide_cursor` preference, which defaults to on.

On Windows with MK8 4.0.1, the fullscreen title screen at 2560×1600 on baseline `5603bfb` (`61dca153…`) still showed the pointer after 2.6 s idle. The host-only rebuild (`2df72e4c…`) hid it after 2.02–2.03 s. Mouse movement, the native F1 menu, the Shift+F1 overlay and F11 each restored it. With the preference disabled, the pointer was still visible after 2.6 s idle. Native tests exercised the timer, focus loss and menu settings. The launcher test verified persistence in Edge. Linux desktop behavior remains unverified. [#143](https://github.com/Vnnc1/MK8-online/issues/143) · [#151](https://github.com/Vnnc1/MK8-online/issues/151)

## MKTV thumbnails: texture read by the CPU — 2026-11-13

### Asynchronous translation and stable 60 FPS (2026-11-07, evening)

**`toolchain/async_submit.py` (default; `MK8_ASYNC_SUBMIT=0` turns it off).** `nvnQueueSubmitCommands` translated the lists to Vulkan before returning, on the game’s own thread, and the time of this translation added to the frame’s. Now submissions, presentations and queue fences enter an ordered queue, served by a single translation thread:
- **Look-ahead:** the game continues immediately and only waits when there are more than `MK8_ASYNC_AHEAD` (default 1) presentations to translate.
- **Fences by ticket:** a queue fence receives the ticket of its own item; a fence recorded in a list receives the ticket of the submission that contains it. The lists are scanned at submission, following `CALL` and `JUMP`.
- **Waits:** `SyncWait` waits for the translation to pass the ticket and then the GPU; `QueueFinish` waits for the whole queue.
- **Concurrency fix:** the queue fence submits the open work on the translation thread itself. An earlier version let `renderer_wait_seq` flush on the game thread, and two threads wrote to the same `VkCommandPool` (`vkBeginCommandBuffer` -13 in the opening logo).
- **Why it is safe:** the translation does not call guest code or the emulated kernel. The lists are only released after another 20,000 lists, and the commands’ textures stay retained.
- **Test:** `tests/test_async_submit.py` uses the real prepared queue. It checks order, fence marking (including in `CALL`/`JUMP`), nothing executed out of order with the translation stopped at a presentation, the fence’s submission number and draining.

**Bounded shader wait now the default (4 ms per frame; `MK8_SHADER_WAIT_MS=-1` returns to the old behavior).** The wait uses 0.5 ms slices measured on the monotonic clock; before, the pthread timeout overshot the deadline (waits of 10–19 ms recorded).

### Blown-out exposure: cause and fix (2026-11-07–08)

**Symptom.** It was not global exposure. Sky, grass and grandstand stayed normal; asphalt, walls, metals and karts (specular reflection) turned white/yellowish. The state was fixed at the start of the race, did not recover and appeared in about half of the GPs (9 of the 11 runs before the fix).

**Cause.** At the start of the race (frames ~2137–2150), the game builds the specular reflection cube array `729c248000` (128×128, 8 mips, 5 cubes, **BC3**) a single time. To do so, it encodes BC3 blocks in a fragment shader and draws each level/layer through an NVN view of format `R32G32B32A32_UINT`, one texel per 4×4 block (32×32 viewport at level 0). The upstream created this view directly on the BC3 Vulkan image, which has no color attachment usage nor `BLOCK_TEXEL_VIEW_COMPATIBLE`. The result is undefined; the AMD driver accepts the view without error. The array was left with whatever was in the image memory, and this array lights all the surfaces with reflection for the rest of the race.

**Fix.** `toolchain/bc_render.py`: a color target that is an uncompressed view of a BC image is drawn into a shadow image of the view’s format, with the size of the level’s block grid. At the end of the pass, the result is copied to that level/layer of the compressed image (`vkCmdCopyImage` between formats of compatible size; extent in texels of the source, one per block). Formats of incompatible size stay as before and are logged. `MK8_BC_RENDER_DIRECT=1` restores the upstream. `tests/test_bc_render.py` exercises levels 0, 3 and 7, the reuse of the shadow, the copy and the cases left as before.

**Result.** 7 consecutive GPs with the fix (`race-grand-prix-fk6jg3u8`, `66yzm6v_`, `yth9gou3`, `g3qjijv6`, `kx663joh`, `daobv8d0`, `oqp67k1r`), all clean: 0.07–0.21% white pixels at frame 3400 and 0.29–0.33% at 3900. ### VRAM and image discard between tracks (2026-11-08)

Resumption of the investigation after 0.1.5, from the context capture provided by the user and from the changes not yet committed. The 0.1.5 setup already contained the texture destruction queue on the translation thread; release through finalization of **memory pools** was a later attempt, with no documented result yet. The test of that attempt (`race-grand-prix-8eno55or`) ended with `window closed` at frame ~37,282, before the final frame 44,000; it does not count as completing the script.

The review found two problems in this attempt:

- The separate list of pools was drained before the next queue item, and could overtake draws already submitted. Now the finalization enters the same ordered queue of submissions, presentations and fences. The synchronous path remains immediate. Ranges with overflow are rejected. After the comparison below, the attempt was left **off by default**: `MK8_RELEASE_POOL_TEXTURES=1` enables it; `MK8_KEEP_POOL_TEXTURES=1` prevails and disables it.

The release also walks the alias table, retires each image once and keeps the backend and its references. Reuse recreates the image and invalidates the upload state. Views/images are destroyed by the existing mechanism, after the submission to the GPU completes. Deferred depth copies are resolved before retiring the source or destination.

A potential use-after-free in `mk8_q_put` was also fixed: the ticket number is now copied before releasing the mutex, since the consumer thread could already free the item before the return.

The age of the listed textures is recorded separately from those aliases. The field formerly called `driver usage` was a VMA estimate: the allocator does not enable `VK_EXT_memory_budget`.
