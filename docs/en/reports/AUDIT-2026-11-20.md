# Audit and consensus — 20/11/2026

Fifteen read-only audits of the project, followed by five consensus reviewers in three rounds. All five reviewers
accepted the final table. This document records what was found, what was proven wrong, and which experiments were run.

Prepared runtime (pre-patch): `local/qualification/builds/4e03c7a323071f8a62ba64ce53cabbf35d307e9186829d9f458cf689d341419c/runtime/runtime/`
Built runtime (patched): the same build's `host-optimized/runtime/`. Logs: `local/qualification/*.log`.

## Consensus verdicts

TRUE (mechanism and cited evidence hold):
S1 (write tracking dead on Linux; cache + texture watch inert), S3 (vk_collect_dead at every submit tail; views/images
only, buffers are freed in vc_free_dead), T1 (first upload hashes with no prior hash), V1 (the 220-539 ms "exec" spikes
are vkQueueSubmit2), V2-V5, Y1 (submission count dominates: ~4.8/frame), Y3 (5,696 zero-draw/zero-pass submits, 28.3%
of submit time), Y4 (conditional-samples waits: 1,617 / 973 ms / worst 114 ms), E1-E3 (frame metric censored, present
flush untimed, n=1 A/B), M1 (backend_pool_written is a no-op despite NVN flush calls), B2 (8-of-32 compile cap;
CPU-second figures unverified), Y2 (compute-submit batching: there is a 5,213 ms submit inside the 5,249 ms csub0
frame).

PARTLY (mechanism right, number/scope/attribution wrong):
D1 (numbers exact but from the patched build and aggregate thread-CPU, not a baseline or frame latency), D2 (gmap
per-stage copy real, "largest per-draw cost" unmeasured), S2 (barrier real but only when an upload CB exists; slot
reuse does wait on completion), S5 (present/acquire stall real; acquire is on the frame thread, present on its own),
C1 (equal-priority starvation real: 10 waits in active1, 1,032 across logs, max 2,504 ms; the 1,018/750 figure was a
command-type count), T5 (584 images / 2,414 MB real but over ~22.7 s, not 10 s), Y5 (86 passes/frame, not 60-70), H1
(scan 88.4-448.6 ms, p50 ~196-202; the 797/739/169/31 numbers are absent), H5 (stdio read path real; 42 us derives
from unverified numbers), M5 (HEAP_MAX ceiling exists; no host release), E4 (ci.yml runs only test_pipeline;
linux.yml adds test_linux_elf; no new-bound test in CI), N4 (deadline is converted from a fresh CLOCK_REALTIME read;
a wall-clock step during a wait can still shift it), L1-L5 (mechanisms, figures partly unverified), F2-F4 (code true;
the 114->71 ms Yaz0 figure came from the auditor's harness, not the repo), B1/B3-B6.

FALSE:
T2 ("per 8 bytes" hash and 2.5-4 GB/s: the hash is four lanes x 32 B/iteration; 61 ms is the whole upload bucket).
H1's exact numbers (see PARTLY).
F5 (no posix_fadvise/readahead anywhere in services/fs.c or archive.c).
C1's 1,018 waits / 750 ms figure.
Y4 was initially reported false by two reviewers and is TRUE (verified: 32 per-second counters sum to 1,617 waits /
973 ms; worst 114 ms at ship3.log:4703).

## Ranked opportunities (surviving the consensus)

1. Measurement first (E1-E3): uncensored frame time (split the blocking acquire out of dt), time `vk_present_flush`,
   paired/repeated runs, separate load and race windows. Every ms comparison before this is host-noise-limited.
2. Y4 conditional-samples wait: 1,617 waits / 973 ms / worst 114 ms. Do not submit at every report: measured attempt
   added ~6,400 submits (+24%) and 129 submits >100 ms (worst 2,388.9 ms) — rejected.
3. Y3 empty submits: 5,696, p50 1.3 ms, 28.3% of submit time; merge/skip the non-WSI one.
4. H1/H2/H4 prefetch scan: 88.4-448.6 ms per scan, runs on the render thread; translation inline; single worker only
   because two globals (maxwell_gmem_base/size) are rewritten; 4 workers proposed.
5. F2 Yaz0: the auditor's harness measured 114->71 ms byte-identical; the repo's copy test now verifies the output (timing deferred).
6. T1/T3/T4 texture first use: skip the first full hash, batch image barriers (~428 at entry), pool ASTC decode.
7. M1 revive write tracking from NVN's `nvnBufferFlushMappedRange`/`nvnMemoryPoolFlushMappedRange` ->
   `backend_pool_written` (currently a no-op); this would activate the 768 MB vertex cache and vcache_above.
8. C1 equal-priority time slice (1,032 core waits, max 2,504 ms).

## Experiments and outcomes (this branch)

| Experiment | Result |
|---|---|
| 3.1 GB heap host-pointer import | cause of 0.4-18 s stalls; capped at 1024 MB (committed `3314a3a`) |
| gmap shaders + BDA off | restores HUD digits that the cap erased; default on (committed) |
| vcache_above | serves above-cap ranges from the device-local cache; inert on Linux until write tracking exists (`fb441ac`) |
| bounded pipeline wait | worst wait 131 -> 3-4 ms; `MK8_INLINE_PIPE=1` restores (committed `e9ae379`) |
| bounded acquire `MK8_ACQUIRE_MS` | guard on the only unbounded WSI wait (committed `e55580f`) |
| present/acquire instrumentation | no `vkQueuePresentKHR` >5 ms in five sessions; the 628 ms stall never reproduced (committed) |
| 512/768 MB caps | rejected: load bursts 0.5-1.1 s (copies above the cap) |
| `MK8_COMPUTE_SUBMIT=0` | rejected: 5,249 ms frame, 9 fps (5,213 ms submit inside exec) |
| MADV_HUGEPAGE before import | rejected: import 3,585 ms vs 724 ms |
| Y4 submit at query end | rejected: +24% submits, 129 submits >100 ms, worst 2,388.9 ms |
| collect_per_frame | unvalidated: its runs were contaminated by the audit load; unwired |
| Yaz0 word/SSE copy | implemented and verified byte-identical by `tests/test_yaz0_native.py::test_copy_path_matches_the_reference` (literals, short/long/overlapping copies, overrun); timing deferred while the host is busy |

## Pending validation (quiet-host block)

**Y3 empty-submit skip was rejected by its first run (20/11/2026):** `MK8_SKIP_EMPTY` hangs the boot — skipping
an empty submission removes the timeline value the guest awaits (`[vk] SyncWait: submission 1 still open after
2 s (submitted 0)`). `toolchain/skip_empty.py` is unwired; the wait/signal diagnostic stays. The original note
follows: Y3 empty-submit skip is implemented in `toolchain/skip_empty.py` behind `MK8_SKIP_EMPTY` (default on; the skip
requires no wait/signal, no upload command buffer, and no draw/pass since the last submission; the profiling
timestamp merges into the next submission). E4 coverage was extended with `tests/test_acquire_bound.py` (default 100 ms, 0 -> UINT64_MAX, 250 and 1 ms),
which passes natively. The y3b variant (E2 + Yaz0 + Y3 + wait/signal) builds (`219/219
unidades`, `BUILD OK`) but the 6000-frame two-track run is blocked: the host stayed at load 12-23 with the UE
servers/CI and 41 GB used, which is the contamination that invalidated two earlier experiments.
